# 气象信息判别器 · weather-rumor-judger-demo

> 别再“最小最大”，用数据说法。  
> 把一句气象信息拆成时间、地点、量级、口径和证据条件，判断它在什么条件下成立。

**作者 / Author：CallMeSUCH**  
GitHub：<https://github.com/CallMeSUCH>

---

## 这是什么

一个面向气象信息素养的规则化判别工具。输入一句天气说法，系统会：

1. 拆解句子中的现象、参数、数值、时间、空间、来源和确定性；
2. 匹配 23 张气象术语判据卡，识别常见口径混淆；
3. 执行逻辑漏洞检查；
4. 给出 A–E 判定与成立条件；
5. 提供官方证据入口，并按需拉取公开数据做交叉核验。

核心原则：

- **不做“绝对真/假”**：信息不足是合法结论；
- **不以 AI 代替证据**：运行时不依赖在线大模型；
- **不以第三方数据冒充官方观测**：数据来源和边界在页面中标注；
- **可复现、可审计**：规则、术语卡、官方链接和拉取时间均可查看。

---

## 主要功能

- 气象说法输入、示例和图片 OCR（本地识别）；
- 句子拆解：现象、参数、数值、时间、窗口、尺度、空间、级别、来源、确定性；
- 23 张术语判据卡：风、降水、温度、台风、海洋、ENSO、概率、比较、时间、水位；
- 常见误用检查：1 小时雨量套 24 小时等级、极大风/最大风/阵风混用、17 级与超强台风混用等；
- A–E 五级判定：
  - A 成立
  - B 条件成立
  - C 术语/逻辑不成立
  - D 信息不足
  - E 与事实不符
- 官方证据与核验入口；
- 实时核验：中央气象台、CMA 台风、NOAA CPC ONI、Open-Meteo、中国天气网等；
- 报告复制 / HTML 下载 / 打印。

## 快速开始

### 方式一：完整版（静态页 + 数据 API）

需要 Python 3.10+，后端只使用标准库。

```bash
python backend/server.py 8766
```

打开：

```text
http://127.0.0.1:8766
```

### 方式二：纯静态版（不拉取实时数据）

```bash
cd web
python -m http.server 8765 --bind 127.0.0.1
```

打开：

```text
http://127.0.0.1:8765
```

> 不要直接双击 `index.html`，浏览器会拦截 `fetch` 读取本地 JSON。

## 数据与标准

术语卡主要依据国家标准、气象业务规定和公开观测规范整理，包括：

- GB/T 35227-2017《地面气象观测规范 风向和风速》
- GB/T 28591-2012《风力等级》
- GB/T 19201-2006《热带气旋等级》
- GB/T 28592-2012《降水量等级》
- GB/T 33666-2017《厄尔尼诺/拉尼娜事件判别方法》
- GB/T 21987-2017《寒潮等级》
- GB/T 29457-2012《高温热浪等级》
- WMO / 地面气象观测规范
- 水利、海洋和防汛相关业务规定

实时数据优先使用官方或可公开验证的接口。部分 CMA 站点档案需要实名账号和 API 权限；未配置时不会返回伪造数据。

**本仓库不包含论文、标准原文 PDF、内部研究文档或问卷原始数据。** 第三方数据和标准的版权、使用条款归原来源所有。

## 边界

- 这是一个演示原型，不是官方预报、预警或灾害判定系统；
- 实时数据可能受接口、缓存、日期和站点覆盖限制；
- 术语卡尚未覆盖全部气象术语；
- 标准会更新，正式使用时应核对现行版本；
- 页面结论用于信息素养与核查训练，不能替代气象、水文、应急部门的正式发布。
