## 0. 先说三件做不到的事

评审前必须先明确边界，否则会误判系统的能力。

**① A 级（成立）和 E 级（与事实不符）在当前实现中不可达。**

`decideVerdict()` 的所有返回路径只有 `B / C / D` 三种。不是遗漏，是能力边界：规则引擎只能判断"术语对不对、口径全不全、实体真不真"，无法确认"这件事到底发生过没有"。给 A 需要官方数据核验，给 E 需要事实反证，两者都超出规则层职责。

界面上的 A–E 五级表是**语义框架**，不是当前系统的输出范围。这一点需要在正式发布前对齐——要么补齐数据核验链路，要么把文案改为"当前可输出 B/C/D"。

**② 不验证事件是否真实发生。**

一句话可以做到"地点真实、术语正确、数值在合理区间"，但事件本身可能是编造的。系统只保证"没有被规则抓住的漏洞"，不保证"事实成立"。

**③ 行政区划库不是权威名录。**

`regions.json` 用于判断"这个地名在已知行政区划里存不存在"，不等于民政部区划代码的权威副本，也不覆盖乡镇/街道级。库中没有 ≠ 该地不存在。

## 1. 判定等级

| 等级 | 名称 | 含义 | 当前可达 |
|---|---|---|---|
| A | 成立 | 术语、口径、证据全部支持 | 否 |
| B | 条件成立 | 术语与口径基本自洽，在特定口径下可成立，仍需核验 | 是 |
| C | 术语/逻辑不成立 | 术语冲突、物理不可能、实体不存在 | 是 |
| D | 信息不足 | 缺时间、地点、口径、证据，或实体无法核实 | 是 |
| E | 与事实不符 | 有反证证明该说法为假 | 否 |

设计原则：**不确定时判 D，不判 B**。D 是合法结论，不是失败。

---

## 2. 判定链（短路顺序）

规则按以下顺序求值，**命中即返回**，后面的检查不再影响判定（但全部会展示给用户）。

```
1. 非地球实体          → C
2. 地理不相容          → C
3. 地点未核实          → D
─────────────────────────────
4. 风速/气温/气压/湿度超物理量级 → C
5. 未来日期按已发生陈述          → D
─────────────────────────────
6. 「超级暴雨」「特大暴雨+1小时」 → C
7. 雨量极值（≥1000mm 且非过程）  → D
8. 「百年一遇」「极大/最大风速」「17级+超强台风」 → B
9. ENSO 缺指数                    → D
─────────────────────────────
10. 兜底：术语/时间/地点等 fail 项 → C 或 D
11. 有术语匹配                    → B
12. 其余                          → D
```

**为什么实体检查必须排在最前**：第 8 步有若干硬编码 `return 'B'` 分支。如果实体校验放在其后，"火星百年一遇暴雨"会被第 8 步直接返回 B，永远走不到实体判断。

## 3. 检查项清单（33 项）

状态含义：`pass` 通过 / `warn` 存疑 / `fail` 不通过。

### 3.1 实体层

| id | 名称 | 触发条件 | 状态 | 影响判定 |
|---|---|---|---|---|
| `location_valid` | 地点真实性 | 识别到非地球实体（火星/月球等） | fail | 是 → C |
| `location_valid` | 地点真实性 | 地名不在区划库，且无上级地名可识别 | fail | 是 → D |
| `location_valid` | 地点真实性 | 地名不在库，但同句有可识别的上级地名 | warn | 否 |

### 3.5 证据与修辞

| id | 名称 | 触发条件 | 状态 | 影响判定 |
|---|---|---|---|---|
| `source` | 来源地址 | 无 URL / 账号 | warn | 否 |

| `reference` | 比较基准 | 史上/以来/同期 | warn | 否 |
| `compare` | 比较是否成立 | 「最强/最大」但无术语支撑 | fail | 否 |

## 4. 关键规则的实现细节

### 4.1 地点三态

| 状态 | 判据 | 处理 |
|---|---|---|
| `verified` | 候选名命中区划库 | pass |
| `partially` | 候选不在库，但同句/同输入有可识别的上级地名 | warn，**不降级** |
| `unverified` | 两者都没有 | fail → D |
| `absent` | 完全没写地名 | fail → D |

`partially` 是为防误伤设计的中间态：真实小地名不该被当成造假。判定为 C 需要"物理不可能"的证据，不能只靠"库里没有"。

### 4.2 地名候选的捕获

```js
/[\u4e00-\u9fa5]{2,6}(?:省|市|县|区|镇|乡|盟|旗)/g
```

排除词：全市、城区、市区、全省、全区、地区、灾区、郊区、景区、山区、库区、牧区。

局限：中文无词边界，正则贪婪匹配会把「浙江安吉县」整体当成一个候选（恰好包含"浙江"，因此判 verified）；但「安吉县」单独出现时依赖库中存在该县名。

### 4.3 单位归一（气压）

| 写法 | 换算 |
|---|---|
| hPa / 百帕 / mb / 毫巴 | 不变 |
| kPa / 千帕 | ×10 |
| Pa / 帕 | ÷100 |

**踩过的坑**：「百帕」字符串包含「帕」。若先判 `/帕/` 再判百帕，1013 百帕会被算成 10.13 hPa，正常气压被判 C。判断顺序必须是"先百帕、后纯帕"。

### 4.4 能见度的特殊处理

只在**带单位**时判断。原因：

- 「能见度 200」可能是 200 米，也可能是 200 公里，差 1000 倍
- 无单位时不做判断，宁可漏报，不可误报

### 4.5 阈值性质说明

所有物理阈值为**量级判断**，不是引用官方标准或世界纪录：

- 气压 800–1100 hPa：地面气压的可能区间，用于发现单位错误（Pa/hPa 混用）
- 风速 ≥100 m/s：远超 17 级上限（约 56–61 m/s），用于发现 km/h 与 m/s 混用
- 气温 ≥60℃ / ≤−90℃：超出地面气温可能范围
- 能见度 >100 km：超出常规观测上限，仅提示核对单位

不要把这些阈值写进论文当作业务标准引用。

## 6. 已知误判风险

| 风险 | 触发场景 | 后果 | 缓解 |
|---|---|---|---|
| 小地名误判 | 只写乡镇名、或库中未收录的旧地名 | 判 D | 提示补上级行政区；`partially` 状态已覆盖部分情况 |
| 无单位数值 | 「能见度 200」「气压 980」 | 不判断 | 设计如此，靠确认页人工补全 |
| 未来日期误判 | 用户填错年份 | 判 D | 提示"要么是预测，要么日期有误" |
| 地理规则误伤 | 海雾出现在大湖（如太湖） | 判 C | 当前规则未覆盖内陆大水域，属已知缺口 |
| 修辞类漏判 | 换用未收录的情绪词 | 不提示 | 词表有限，需持续补充 |
| 事实层面无能力 | 真实地点 + 合理数值 + 虚构事件 | 可能判 B | 需数据核验，非规则层能解决 |

## 附：评审建议关注点

1. **A/E 不可达**是否符合产品预期？若需要，应补数据核验链路，而非改规则。
2. **阈值全部是量级判断**，是否需要替换为有出处的业务标准？
3. **`partially` 状态的取舍**：宁放过小地名，也不误伤——这个方向是否认同？
4. **地理相容只做了"沿海"一条规则**，内陆大水域、沙漠、高原尚未覆盖。
5. **33 项检查中只有 12 项实际影响判定**（`decideVerdict` 引用了 13 个 id，其中 `term` 永远不为 fail），其余仅作提示。这个比例是否合理？不可达分支是否要清理？
